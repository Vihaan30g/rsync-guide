1. What is rsync?

rsync (remote sync) is a command-line tool that copies and synchronizes files and directories, either locally or between machines. It is installed by default on most Linux distributions and has been a standard tool since 1996.

Unlike cp or scp, which blindly copy everything, rsync compares source and destination first and transfers only what is different.

2. How rsync works

  1. Connection. For remote transfers rsync usually tunnels through SSH. It starts an rsync process on both machines, which is why rsync must be installed on both ends.
  2. File list. The sender builds a list of files to consider, with sizes and modification times.
  3. Quick check. By default, a file is skipped if its size and modification time already match on the receiver.
  4. Delta transfer. For files that changed, rsync splits the receiver's copy into blocks and compares rolling and strong checksums, so only the differing blocks are sent.
  5. Finalize. The receiver rebuilds the file, then applies the permissions and timestamps (with -a).
Consequence: if a transfer is interrupted, re-running the same command skips what was already copied instead of starting over.

3. Why it is useful

  • Large datasets. Datasets, logs, backups and recordings can reach tens of GB. Interrupted copies can simply be resumed.
  • Repeatable. After recording more data, run the same command and only new files move.
  • Preserves metadata. Permissions and timestamps are kept, which matters for backups and reproducible data.
  • No extra software beyond SSH, no USB drives, no cloud upload.
  • Works for any data: code, media, datasets, backups, or sensor recordings such as ROS 2 bag files (the example used in this guide).
  • Visible progress per file, with speed and ETA.

4. Example setup used in this guide

The assumed audience is comfortable with Linux, ROS 2 and basic networking. In the videos, an NVIDIA Jetson Orin sends a folder of recorded robot data to a workstation, but the steps are identical for any two Linux machines. We connect them directly with an Ethernet cable and give each a static IP on the same subnet. No router is needed.

DeviceRoleUserIP addressSubnet mask
WorkstationDestinationmarsuser192.168.10.1255.255.255.0
Jetson OrinSourcemarsorin192.168.10.2255.255.255.0

In the example, data moves from the Orin: /home/marsorin/rosbag/acads_floor2_1/ to the workstation: /home/marsuser/rosbags/.

Step 1: Set a static IP on the workstation

Connect the Ethernet cable, then open Settings → Network, select the wired connection, and under IPv4 choose Manual:

FieldValue
Address192.168.10.1
Netmask255.255.255.0
Gatewayleave empty

Toggle the connection off and on to apply it.

Step 2: Install and check the SSH server on the workstation

rsync connects over SSH, so the receiving machine must run an SSH server.

sudo apt update
sudo apt install openssh-server
sudo systemctl status ssh

The status output should show active (running). Press q to exit the status view.

Step 3: Configure the Orin, install SSH, check rsync

On the Orin, set the wired connection manually the same way as Step 1, using 192.168.10.2 and 255.255.255.0. Then test the link to the workstation:

ping 192.168.10.1

Replies mean the cable and IPs are fine. Stop with Ctrl+C. Next install SSH:

sudo apt update
sudo apt install openssh-server
If the install fails or asks you to run another command. In the video, the install was interrupted with a message about an unfinished package configuration. The fix is to run the suggested command, then repeat the install: 
sudo dpkg --configure -a
sudo apt install openssh-server
dpkg --configure -a finishes configuring packages left half-installed by an earlier interrupted install or update.

Now check that rsync exists and that SSH is running:

rsync --version
sudo systemctl status ssh

If rsync --version says the command is not found, install it with sudo apt install rsync.

Step 4: Create the destination folder on the workstation

On the workstation, create the folder that will receive the data. Confirm your user name first:

whoami
cd ~
ls
mkdir rosbags
ls
cd rosbags/

The prompt should now end in ~/rosbags, which is /home/marsuser/rosbags.

Step 5: Run rsync from the Orin

On the Orin terminal, run:

rsync -avh --progress /home/marsorin/rosbag/acads_floor2_1/ marsuser@192.168.10.1:/home/marsuser/rosbags/

The first connection asks you to confirm the host fingerprint (type yes) and then for the workstation user's password.

Command breakdown

PartMeaning
-aArchive mode: recursive, and preserves symlinks, permissions, times, owner and group. Standard for directory copies.
-vVerbose: lists the files being transferred.
-hHuman-readable sizes (MB, GB).
--progressShows progress, speed and time remaining per file.
/home/marsorin/rosbag/acads_floor2_1/Source directory.
marsuser@192.168.10.1:/home/marsuser/rosbags/Destination in the form user@host:path.
The trailing slash matters. acads_floor2_1/ copies the contents of the folder into rosbags/. Without the slash, rsync creates rosbags/acads_floor2_1/. Use the one you want.

Step 6: Confirm completion on the Orin

When finished, rsync prints a summary with the bytes sent, the speed, and the total size. The prompt returns with no error messages.

Step 7: Verify the data on the workstation

On the workstation, check the copied files:

ls -lh ~/rosbags
du -sh ~/rosbags

Compare the total size with the source. You can also open a few files to confirm they are intact.

Useful options

OptionUse
-n / --dry-runShow what would be copied without copying. Great for testing a command.
--partialKeep partly transferred files so a resume continues from there. -P equals --partial --progress.
-zCompress during transfer. Helps on slow links, but little use for already-compressed data such as videos, images or archives.
-cCompare by checksum instead of size and time (slower, more thorough).
--deleteRemove files on the destination that no longer exist on the source. Dangerous: test with -n first.
--bwlimit=KBPSLimit bandwidth.

To pull data instead of pushing, run on the workstation: rsync -avh --progress marsorin@192.168.10.2:/home/marsorin/rosbag/ ~/rosbags/

Troubleshooting

ProblemLikely cause and fix
Ping failsCheck the cable, that both IPs are on 192.168.10.x, and the mask is 255.255.255.0.
Connection refusedSSH server is not running on the workstation. Run sudo systemctl start ssh.
Permission deniedWrong user or password, or no write permission on the destination folder.
rsync: command not foundInstall on both machines: sudo apt install rsync.
Interrupted transferRun the same command again; completed files are skipped.
